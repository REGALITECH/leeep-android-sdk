# 0.10.0

## 変更内容

`Leeep.setup(context, websiteId)` を追加し、計測に使う端末 ID をアプリの再起動後も保持できるようにしました。これにより、起動をまたいだ閲覧と注文を同じ端末の計測として関連付けられます。

ID はアプリのバックアップ対象外の領域へ保存します。アンインストールや「データを消去」後は新しい ID になります。保存した値が壊れている場合も再作成し、読み書きに失敗した場合はプロセス内の一時 ID で計測を続けます。

## 更新時の対応

SDK のバージョン更新とあわせて、初期化を次の形式に変更してください。`Application.onCreate` など、最初の計測送信・タグ表示より前に呼び出します。

```kotlin
// 変更前
Leeep.setup(websiteId)

// 変更後（Application 内の例）
Leeep.setup(this, websiteId)
```

旧 `Leeep.setup(websiteId)` は非推奨になりました。旧 API のままでは起動ごとに ID が変わる従来の動作が続き、今回の改善は適用されません。`allWarningsAsErrors` などで警告をエラーとして扱うアプリでは、旧 API の呼び出しを変更するまでビルドに失敗する場合があります。

初期化時に小さなファイルを同期で読み書きするため、StrictMode でディスクアクセスを検出するアプリでは警告が出る場合があります。導入アプリでビルド・初期化・タグ表示・注文計測を確認し、アプリ再起動後も計測 ID が保持されることを確認してください。
